# Словарь архитектурных терминов Spine

Этот файл объясняет по-русски технические термины из
[ARCHITECTURE.md](ARCHITECTURE.md). Английское написание приводится в заголовке
термина только для сопоставления с архитектурой, исходным кодом и документацией
используемых библиотек.

Специфические понятия предметной области зафиксированы в
[`CONTEXT.md`](../CONTEXT.md). Здесь собраны также общие понятия разработки,
данных, искусственного интеллекта и эксплуатации.

## Общая структура системы

**module (Модуль)** — часть системы с определённым интерфейсом и скрытой за ним
реализацией. Модулем может быть функция, пакет исходного кода или целый слой.

**interface (Интерфейс)** — всё, что должен знать вызывающий код: доступные
операции, форматы данных, гарантии, ограничения и возможные ошибки.

**contract (Контракт)** — формально определённые входные и выходные данные и
гарантии взаимодействия между модулями.

**schema (Схема данных)** — машиночитаемое описание допустимой структуры и типов
данных, применяемое для проверки и генерации кода.

**typed (Типизированный)** — имеющий явно заданную и проверяемую структуру, а не
представленный произвольным набором полей или текстом.

**seam (Шов замены)** — место, в котором одну реализацию можно заменить другой
без изменения вызывающего кода.

**adapter (Адаптер)** — реализация интерфейса для конкретной технологии или
внешней системы. Например, отдельный адаптер связывает Spine с Cognee.

**modular monolith (Модульный монолит)** — одно приложение с чёткими внутренними
модулями. Такая структура позволяет не вводить микросервисы до появления
эксплуатационной необходимости.

**control plane (Контур управления)** — часть системы для управления
определениями, версиями, правами, развёртываниями и настройками.

**execution plane (Контур исполнения)** — часть системы, непосредственно
выполняющая агентов, процессы, инструменты и шаги с участием человека.

**context plane (Контур контекста)** — часть системы для получения,
нормализации, индексирования и выдачи корпоративного контекста.

**assurance plane (Контур обеспечения качества)** — часть системы для проверок
качества, телеметрии, аудита и контроля перед выпуском версий.

**worker (Фоновый обработчик)** — отдельный процесс, который получает и
асинхронно выполняет задачи определённого типа.

**stateless (Компонент без собственного состояния)** — компонент, который не
хранит обязательное состояние между запросами в памяти процесса. Всё нужное
состояние можно восстановить из устойчивого хранилища.

**vertical slice (Вертикальный срез)** — минимальная сквозная реализация
пользовательского сценария: данные, серверная логика, агент или процесс,
проверки и интерфейс.

## Источники и данные

**source of truth (Источник истины)** — авторитетное место, по которому
определяется текущее состояние данных. Для состояния Spine это PostgreSQL, а для
объекта внешней системы — сама внешняя система.

**canonical model (Каноническая модель)** — нормализованное внутреннее
представление бизнес-объекта, не зависящее от формата конкретного источника.

**projection (Проекция)** — производное представление данных, подготовленное для
определённой задачи и допускающее перестроение из источника истины.

**immutable object (Неизменяемый объект)** — запись, которую после создания не
редактируют. Изменение представляется новой версией.

**`SourceObject` (Объект источника)** — устойчивое представление объекта,
наблюдаемого во внешней системе.

**`SourceRevision` (Ревизия источника)** — конкретная неизменяемая версия объекта
источника с контрольной суммой, временем наблюдения и происхождением.

**checksum (Контрольная сумма)** — вычисляемый отпечаток содержимого для проверки
целостности и обнаружения повторов.

**provenance (Происхождение данных)** — сведения о том, из какого источника,
ревизии и фрагмента получены данные и какими преобразованиями они созданы.

**stable locator (Устойчивый указатель)** — адрес фрагмента источника, который
можно воспроизвести: страница документа, строка таблицы, идентификатор сообщения
или диапазон символов.

**evidence (Доказательство)** — проверяемая ссылка на конкретную ревизию и
фрагмент источника, подтверждающий вывод или действие.

**raw payload (Исходные данные)** — ответ внешней системы в первоначальном виде,
до нормализации и возможной потери специфических полей.

**object storage (Объектное хранилище)** — хранилище файлов и двоичных объектов,
например S3 или MinIO.

**tombstone (Отметка об удалении)** — запись о том, что объект удалён в
источнике. Она сохраняет историю и позволяет исключить объект из новых
проекций.

**retention policy (Политика хранения)** — правила, определяющие сроки хранения
и удаления разных категорий данных.

## Загрузка и синхронизация

**ingestion (Загрузка данных)** — управляемый приём данных из внешнего источника,
сохранение оригинала, создание ревизии, нормализация и запуск проекций.

**connector (Соединитель)** — адаптер внешней системы, который принимает
уведомления или читает её программный интерфейс с учётом позиции синхронизации,
ограничений частоты и правил повторов.

**webhook (Веб-уведомление)** — вызов по протоколу HTTP, которым внешняя система
сообщает Spine о произошедшем событии.

**incremental sync (Добавочная синхронизация)** — загрузка только тех изменений,
которые появились после предыдущей успешно сохранённой позиции.

**`SyncCursor` (Позиция синхронизации)** — сохранённая отметка, с которой нужно
продолжить добавочную синхронизацию.

**normalization (Нормализация)** — преобразование данных конкретного источника в
типизированные канонические объекты Spine.

**identity resolution (Сопоставление идентичности)** — определение того, какие
записи из разных источников обозначают одного человека, организацию, проект или
другой объект.

**transactional outbox (Транзакционная очередь исходящих событий)** — сохранение
бизнес-изменения и будущего события в одной транзакции PostgreSQL. Отдельный
обработчик затем доставляет событие адресату.

**at-least-once delivery (Доставка не менее одного раза)** — гарантия, при
которой событие не теряется, но иногда приходит повторно. Поэтому обработчик
должен безопасно принимать повторы.

**idempotency (Идемпотентность)** — свойство операции, при котором повтор команды
с тем же ключом не создаёт повторного эффекта.

**retry (Повтор операции)** — повторное выполнение после временной ошибки.

**exponential backoff (Экспоненциальная задержка)** — увеличение времени ожидания
между последовательными повторами операции.

**jitter (Случайный разброс задержки)** — небольшое случайное изменение времени
ожидания, предотвращающее одновременный повтор большого числа обработчиков.

**quarantine, dead-letter (Карантин ошибочных сообщений)** — изолированное
хранение необработанного объекта или события для диагностики без остановки всей
загрузки.

## Граф контекста и поиск

**Context Graph (Граф контекста)** — версионируемая семантическая проекция
сущностей, отношений и онтологии, связанная с доказательствами из конкретных
ревизий источников.

**graph database (Графовая база данных)** — база данных, приспособленная для
хранения вершин, рёбер и переходов по связям между ними.

**entity (Сущность)** — различимый объект предметной области: человек,
организация, проект, документ или продукт.

**relation (Отношение)** — типизированная смысловая связь между двумя сущностями.

**ontology (Онтология)** — версия допустимых типов сущностей и отношений, их
синонимов и правил извлечения или проверки.

**`OntologyCandidate` (Предложение изменения онтологии)** — ещё не опубликованный
новый тип, отношение или правило, предложенные системой или человеком.

**chunk (Фрагмент)** — часть документа или другого источника, достаточно
небольшая для индексирования и передачи модели и сохраняющая ссылку на исходное
место.

**embedding (Векторное представление)** — числовой вектор, представляющий смысл
текста или объекта для поиска семантически похожих элементов.

**vector store (Векторное хранилище)** — индекс векторных представлений,
выполняющий поиск по их близости.

**full-text search (Полнотекстовый поиск)** — поиск по словам и их формам, а не
по смысловой близости.

**hybrid retrieval (Гибридный поиск)** — совместное использование векторного,
полнотекстового, атрибутивного и графового поиска.

**graph traversal (Обход графа)** — переход от сущности к связанным с ней
сущностям по рёбрам графа.

**multi-hop retrieval (Многошаговый поиск)** — поиск ответа через несколько
последовательных связей графа.

**Context Broker (Посредник контекста)** — интерфейс Spine, который проверяет
права и профиль контекста, обращается к адаптеру проекции и возвращает
структурированный результат поиска.

**`ContextProfile` (Профиль контекста)** — версионируемое описание разрешённых
источников, способов поиска, глубины обхода графа, требований к свежести и
допустимого объёма контекста агента.

**`RetrievalResult` (Результат поиска)** — структурированный набор фрагментов,
сущностей, отношений, ссылок, способа поиска и версии проекции.

**`ContextBundle` (Пакет контекста)** — сохранённый набор контекста и
доказательств, фактически выданный конкретному запуску агента.

**`ProjectionCommand` (Команда проекции)** — идемпотентная команда адаптеру на
построение или обновление графа контекста из конкретных ревизий источников.

**`ProjectionReceipt` (Отчёт о проекции)** — результат работы адаптера:
соответствия идентификаторов, количества объектов, предупреждения, ошибки и
технические версии реализации.

**`ProjectionVersion` (Версия проекции)** — закреплённая версия графа контекста с
определёнными состоянием, онтологией и настройками.

**shadow projection (Теневая проекция)** — новая версия проекции, построенная
рядом с активной, но ещё не обслуживающая рабочие запросы.

**reindex, rebuild (Повторное индексирование)** — повторное построение индексов и
графа из оригиналов, ревизий источников и закреплённых настроек.

## Искусственный интеллект и генерация ответов

**Q&A, Questions and Answers (Вопросы и ответы)** — сценарий, в котором
пользователь задаёт вопрос по внутренним материалам и получает ответ с
доказательствами.

**AI, Artificial Intelligence (Искусственный интеллект)** — общее название
методов, выполняющих задачи, которые обычно требуют человеческого анализа или
генерации.

**LLM, Large Language Model (Большая языковая модель)** — модель, принимающая
текстовый или мультимодальный контекст и создающая ответ.

**model provider (Поставщик модели)** — организация или программный интерфейс,
предоставляющие доступ к языковой модели.

**prompt (Запрос к модели)** — инструкции и входные данные, передаваемые
языковой модели.

**token (Токен)** — фрагмент текста, в единицах которого модель измеряет объём
входа, выхода и стоимость обработки.

**context window (Окно контекста)** — максимальное число токенов, которое модель
может учитывать за один вызов.

**RAG, Retrieval-Augmented Generation (генерация с дополнением найденными
данными)** — создание ответа после поиска подходящего корпоративного контекста.

**groundedness (Подтверждённость источниками)** — степень, в которой ответ
опирается на переданные источники, а не только на знания или предположения
модели.

**hallucination (Галлюцинация модели)** — правдоподобное, но не подтверждённое
входными данными или источниками утверждение.

**abstention (Отказ от ответа)** — явное сообщение о невозможности ответить из-за
недостатка доступных доказательств.

**confidence (Уверенность)** — оценка уверенности реализации в результате. Она
не является самостоятельным доказательством корректности.

**LLM-as-a-judge (Модель в роли проверяющего)** — использование языковой модели
как одной из проверок качества. Такая проверка дополняет, но не заменяет точные
правила и размеченные человеком примеры.

## Агенты и инструменты

**`Capability` (Способность)** — стабильный версионируемый контракт одного вида
работы с типизированными входными и выходными данными.

**`Agent` (Агент)** — зарегистрированный специализированный исполнитель одной
или нескольких связанных способностей.

**`AgentVersion` (Версия агента)** — неизменяемая версия агента с закреплёнными
обработчиками, запросами к модели, моделями, профилями контекста, инструментами,
ограничениями и проверками качества.

**`AgentBinding` (Привязка агента)** — правило выбора конкретной версии агента
для способности в заданных рабочем пространстве, среде или процессе.

**`AgentHandler` (Обработчик агента)** — небольшой интерфейс локальной реализации
способности, не зависящий от агентского каркаса.

**`AgentExecutionContext` (Контекст исполнения агента)** — сведения об одном
запуске: субъект, рабочее пространство, среда, идентификаторы, предельное время,
разрешения, события и сигнал отмены.

**`AgentPackage` (Пакет агента)** — версионируемый комплект реализации агента:
описание, обработчики, схемы, навыки, тесты и проверки качества.

**manifest (Описание пакета)** — машиночитаемое описание содержимого и требований
пакета.

**`Skill` (Навык)** — переиспользуемый набор инструкций, справочных материалов,
ресурсов и объявленных утилит внутри реализации агента. Навык не является
способностью или процессом.

**`Tool` (Инструмент)** — контролируемая операция, доступная агенту через
типизированные схемы входа и выхода и явно выданное разрешение.

**Tool Gateway (Шлюз инструментов)** — единая точка вызова инструментов,
проверяющая разрешения, время выполнения, идемпотентность, сокрытие чувствительных
данных и аудит.

**model profile (Профиль модели)** — версионируемый выбор модели и разрешённых
параметров её вызова.

**prompt version (Версия запроса к модели)** — неизменяемая версия инструкций или
шаблона запроса.

**structured output (Структурированный ответ)** — ответ модели, проверяемый по
заданной схеме, а не представленный произвольным текстом.

**framework-independent (Независимый от каркаса)** — не требующий классов или
типов LangChain, LangGraph, Agno либо другого агентского каркаса.

**runtime (Среда исполнения)** — модуль запуска закреплённой реализации агента,
не владеющий долгоживущим состоянием процесса.

**cooperative cancellation (Совместная отмена)** — способ отмены, при котором
обработчик регулярно проверяет сигнал и корректно прекращает работу.

**`EventSink` (Приёмник событий)** — интерфейс отправки событий о ходе работы,
вызовах инструментов и использовании ресурсов без раскрытия скрытых рассуждений
модели.

## Процессы и контроль качества

**`Workflow` (Рабочий процесс)** — версионируемая схема бизнес-процесса из шагов,
выполняемых агентами, кодом, людьми, вложенными процессами и проверками.

**durable workflow (Долговечный процесс)** — процесс, состояние которого
сохраняется и восстанавливается после перезапуска или длительного ожидания.

**`WorkflowDefinition`, `WorkflowVersion` (Определение и версия процесса)** —
идентичность процесса и его неизменяемая опубликованная версия.

**`WorkflowRun` (Запуск процесса)** — конкретное исполнение закреплённой версии
процесса.

**`Step` (Шаг)** — один узел процесса. Его конкретное исполнение называется
запуском шага (`StepRun`).

**`Activity` (Операция Temporal)** — выполняемая от имени процесса операция с
внешним вводом-выводом или недетерминированной работой.

**`Signal` (Сигнал Temporal)** — асинхронное уведомление уже запущенного процесса.

**`Update` (Обновление Temporal)** — запрос к запущенному процессу, который может
проверить и изменить его состояние и вернуть результат.

**`Timer` (Таймер)** — сохраняемое ожидание заданного момента времени внутри
процесса.

**`Child Workflow`, `subworkflow` (Дочерний процесс)** — отдельный процесс,
запущенный родительским процессом и связанный с ним.

**`Artifact` (Артефакт)** — типизированный сохраняемый результат шага с версией и
историей происхождения.

**lineage (Цепочка происхождения)** — входные данные, предшествующие артефакты и
преобразования, из которых получен результат.

**`Handoff` (Передача результата)** — передача артефакта следующему участнику
процесса с явным контрактом качества.

**`Evaluation`, `eval` (Проверка качества)** — воспроизводимая проверка результата,
поиска, модели, агента или обнаружителя ситуации.

**`Evaluator` (Проверяющий)** — конкретная реализация проверки качества.

**`Gate` (Контрольный переход)** — решение о дальнейшем маршруте на основе
политики или результатов проверок качества.

**release gate (Проверка перед выпуском)** — обязательный набор проверок перед
публикацией новой версии.

**human-in-the-loop (Участие человека)** — обязательное участие человека в
проверке, редактировании или разрешении действия.

**`Approval` (Согласование)** — зафиксированное разрешение или отказ для
предлагаемого действия.

**fallback (Запасной маршрут)** — переход на альтернативную реализацию или
маршрут после ошибки либо неудовлетворительного результата.

**replay (Повторное воспроизведение)** — повтор обработки на сохранённых входных
данных для проверки новой версии или расследования ошибки.

## Доступ и безопасность

**`Workspace` (Рабочее пространство)** — основная граница изоляции данных одной
организации в Spine.

**tenant, multi-tenancy (Клиент и многоклиентность)** — организация-клиент и
способность одной установки безопасно обслуживать несколько изолированных
организаций.

**`Environment` (Среда)** — изолированный контур разработки, предварительной
проверки или промышленной эксплуатации внутри рабочего пространства.

**RBAC, Role-Based Access Control (Ролевое управление доступом)** — выдача прав
на основе роли пользователя.

**ABAC, Attribute-Based Access Control (Атрибутивное управление доступом)** —
выдача прав на основе свойств пользователя, ресурса, среды и цели обращения.

**ACL, Access Control List (Список управления доступом)** — перечень субъектов и
разрешённых им операций над конкретным объектом.

**RLS, Row-Level Security (Защита строк базы данных)** — дополнительная проверка
доступа к отдельным строкам на уровне PostgreSQL.

**grant (Разрешение)** — явно выданное право использовать инструмент, источник
или внешнюю операцию в заданных пределах.

**`acting_on_behalf_of` (Действующий от имени)** — субъект, от имени которого
агент выполняет текущий запуск и чьи полномочия ограничивают доступ.

**service principal (Техническая учётная запись)** — идентичность фонового
обработчика, соединителя или развёрнутого агента.

**least privilege (Минимальные полномочия)** — выдача только необходимых прав и
на минимально необходимое время.

**PII, Personally Identifiable Information (Персональные данные)** — сведения,
позволяющие идентифицировать человека.

**redaction (Сокрытие данных)** — удаление или маскирование чувствительных данных
перед передачей модели, в телеметрию или во внешнюю систему.

**prompt injection (Внедрение инструкции)** — вредоносная инструкция внутри
источника, пытающаяся изменить поведение агента или получить неразрешённый
доступ.

## Публикация и эксплуатация

**deployment (Развёртывание)** — публикация конкретной версии агента, процесса
или другого исполняемого определения в заданной среде.

**development (Среда разработки)** — среда для разработки и ранней проверки.

**staging (Предварительная среда)** — изолированная среда проверки перед
промышленной эксплуатацией.

**production (Промышленная среда)** — среда, обслуживающая реальные рабочие
процессы.

**shadow (Теневой режим)** — новая версия выполняется или индексируется рядом с
действующей, но не влияет на рабочие ответы и действия.

**canary (Канареечный выпуск)** — новая версия получает ограниченную долю
реальной нагрузки для контролируемой проверки.

**rollback (Откат)** — возврат к предыдущей рабочей версии после обнаружения
проблемы.

**feature flag (Переключатель возможности)** — управляемое включение функции без
отдельного развёртывания кода.

**cache (Кэш)** — временное ускоряющее хранилище, которое не является источником
истины.

**rate limit (Ограничение частоты)** — предел числа операций за заданный период.

**timeout, deadline (Ограничение времени и крайний срок)** — максимальная
длительность операции и абсолютный момент, после которого работа должна
прекратиться.

**SLA, Service Level Agreement (Соглашение об уровне обслуживания)** — заданные
требования к качеству услуги, например к допустимому времени ответа.

## Наблюдаемость и интерфейс

**observability (Наблюдаемость)** — возможность понять состояние системы по
трассам, метрикам и журналам.

**telemetry (Телеметрия)** — технические сведения о работе системы: события,
время выполнения, ошибки, расход токенов и стоимость.

**trace (Трасса)** — связанная цепочка операций одного запроса или запуска
процесса.

**`trace_id` (Идентификатор трассы)** — значение, объединяющее связанные операции
во всех модулях.

**span (Участок трассы)** — вложенная операция внутри общей трассы, например
отдельный вызов модели или инструмента.

**audit log (Журнал аудита)** — неизменяемый журнал значимых действий, решений и
изменений настроек.

**latency (Задержка)** — время от начала операции до получения результата.

**drift (Дрейф качества)** — постепенное изменение поведения модели, поиска или
версии агента относительно проверенного исходного уровня.

**API, Application Programming Interface (Программный интерфейс)** — формальный
способ взаимодействия модулей или внешних систем.

**endpoint (Операция программного интерфейса)** — конкретная операция HTTP с
определёнными адресом, методом и форматом запроса и ответа.

**OpenAPI (Описание HTTP-интерфейса)** — машиночитаемое описание операций,
форматов запросов и ответов, из которого Spine создаёт типы и клиентский код.

**SDK, Software Development Kit (Набор средств разработки)** — библиотека и
вспомогательные средства для интеграции внешнего кода с платформой.

**MCP, Model Context Protocol (Протокол контекста модели)** — протокол
подключения моделей и агентов к внешним инструментам и источникам контекста. Сам
по себе протокол не выдаёт разрешение на доступ.

**CLI, Command-Line Interface (Интерфейс командной строки)** — управление
программой с помощью команд в терминале.

**DAG, Directed Acyclic Graph (Ориентированный ациклический граф)** —
ориентированный граф без циклов, часто используемый для представления процесса.

**SSE, Server-Sent Events (События от сервера)** — передача потока событий от
сервера браузеру по одному HTTP-соединению.

**read model (Модель чтения)** — представление данных, подготовленное для
быстрого чтения интерфейсом или отчётом.

**materialized projection (Материализованная проекция)** — заранее вычисленная
модель чтения, обновляемая при изменении исходных данных.

## Используемые технологии

**PostgreSQL (реляционная база данных)** — целевой источник истины для состояния,
которым владеет Spine.

**Cognee (средство построения графа контекста)** — библиотека для создания
семантической графовой и векторной проекции. В Spine она подключается через
адаптер проекции контекста.

**Neo4j (графовая база данных)** — один из рассматриваемых вариантов
промышленного хранилища графа контекста.

**pgvector (расширение для векторного поиска)** — расширение PostgreSQL для
хранения векторных представлений и поиска по их близости.

**Redis (хранилище в памяти)** — средство для кэша и краткоживущей координации,
но не источник истины Spine.

**S3 и MinIO (объектные хранилища)** — совместимые средства хранения оригиналов,
вложений и исходных данных.

**FastAPI (каркас HTTP-интерфейса)** — программный каркас на Python для создания
серверного интерфейса Spine.

**Pydantic (средство проверки моделей данных)** — библиотека Python для описания
и проверки типизированных моделей и внешних контрактов.

**SQLAlchemy (средство работы с базой данных)** — набор средств Python для работы
с реляционной базой данных.

**Alembic (средство изменения схемы базы данных)** — средство версионирования и
применения изменений схемы базы данных.

**Temporal (платформа исполнения долговечных процессов)** — хранит историю
процесса и обрабатывает таймеры, повторы, сигналы и обновления.

**OpenTelemetry (стандарт наблюдаемости)** — открытый стандарт трасс, метрик и
журналов.

**Langfuse (система наблюдаемости языковых моделей)** — средство управления
запросами к модели и проверки качества её вызовов.

**LiteLLM (единый интерфейс языковых моделей)** — библиотека Python для обращения
к разным поставщикам языковых моделей.

**LangChain (каркас разработки агентов)** — необязательное средство интеграции
моделей и построения готовых циклов работы агента с инструментами.

**LangGraph (каркас графовой логики агента)** — необязательное средство для
логики внутри одного обработчика агента. В Spine оно не заменяет Temporal.

**React и Next.js (средства создания веб-интерфейса)** — библиотека и программный
каркас, на которых строится веб-интерфейс Spine.

**TanStack Query (средство управления серверными данными)** — библиотека
управления данными, получаемыми веб-интерфейсом от сервера.

**React Flow (редактор графов)** — библиотека для визуального отображения и
редактирования графов и схем процессов.

**Storybook (среда разработки элементов интерфейса)** — изолированное средство
разработки и проверки элементов пользовательского интерфейса.

**Playwright (средство проверки веб-интерфейса)** — управляет браузером и
выполняет сквозные автоматизированные проверки.

**Testcontainers (средство интеграционного тестирования)** — запускает временные
инфраструктурные зависимости в контейнерах для интеграционных проверок.
