Report visibility linearizes at the successful PostgreSQL UoW commit. Report
metadata, source links, the success audit event and the artifact's committed
state participate in that transaction. `authorize_commit` executes after
payload and metadata preparation, while source and retention locks remain held,
immediately before the transaction can publish. Callback denial, exception,
cancellation, audit insertion failure or transaction failure rolls back the
report and success receipt together. A lost response after commit is resolved
by a new request that rechecks current authorization before returning the
stable report identity.

The shared source-lock order is lifecycle shared lock, workspace/environment
generation, exact revision admission lock, current source head, exact-source
retention applicability pointer, then current AccessPolicy pointer. The
canonical applicability writer uses row lock plus generation CAS. The
synthetic PostgreSQL test verifies source lifecycle and retention replacement
interleavings with deterministic barriers. AccessPolicy activation/revocation
and all possible canonical source writers still require full contract-level
concurrency qualification; external approval authorities cannot be serialized
by the database unless their revocation protocol participates in this UoW.

## Evidence and limits

The vertical slice test is
`test_postgresql_private_asr_authorized_synthetic_report_commit`. It uses an
isolated PostgreSQL service, current Alembic migrations, `spine_runtime`, real
canonical source/head and AccessPolicy records, the canonical retention
applicability repository, deterministic test-only approved terms, concrete
source locks, concrete storage, and canonical UoW audit persistence. It checks
authorized read, exact lineage and expiry, denial/exception/audit failure,
concurrent duplicate visibility, retention replacement and lifecycle fencing.
No aggregate is made visible.

The test-only terms authority is available solely through explicit test
composition. It cannot be registered by production wiring. A production
storage instance with missing approval/terms providers denies. The opaque
`profile_ref` is accepted only as a typed reference to an applicability kind;
the resolver then loads and verifies the canonical database binding. UUID
equality is not proof of policy authority.

The report manifest metadata migration is `20261229_97`, following the branch's
supported predecessor chain. It adds report manifest identity and complete
source binding fields; it does not create another manifest registry. Frozen
dataset versions and #661 thresholds are unchanged.

Required remaining gates include the full restricted-role race matrix,
production-approved terms and manifest authority composition, aggregate
publication, process crash/restart, restore reconciliation, backup deletion,
physical erasure, encryption-at-rest and named-environment operator evidence.
No production approval or readiness is claimed. Keep PR #797 OPEN/DRAFT and
Issue #795 OPEN until all required acceptance evidence exists.
